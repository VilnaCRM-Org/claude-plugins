# Project Profile Schema — `.claude/react-sdlc.yml`

The project profile is the single source of truth that generalizes every
command, agent, and skill in this plugin to a concrete React frontend
repository (the VilnaCRM SPA template lineage). It lives at
`.claude/react-sdlc.yml` in the target repository, is generated by
`/fe-sdlc-setup` (`scripts/generate-profile.sh`), and is validated by
`scripts/validate-profile.sh` before every SDLC stage.

This document is the **canonical key list**: the `profile-keys-check` lint
greps each skill's `## Profile keys consumed` header against the keys
documented here. A key consumed by a skill but absent from this page fails
the build.

## Top-level keys

| Key              | Required | Type | Default | Notes                                                                       |
| ---------------- | -------- | ---- | ------- | --------------------------------------------------------------------------- |
| `schema_version` | yes      | int  | —       | Must be `1`. Bumped only on breaking schema changes (plugin MAJOR release). |

## `project`

| Key            | Required | Type   | Default | Notes                                              |
| -------------- | -------- | ------ | ------- | -------------------------------------------------- |
| `project.name` | yes      | string | —       | Short app name; used in reports and issue/PR text. |
| `project.repo` | yes      | string | —       | GitHub `owner/name`; consumed by `gh` calls.       |

## `framework`

The frontend stack descriptor. `framework.ui` is the one required key (it
drives component, styling, and review guidance); the rest are informational
and let skills tailor prose to the detected toolchain. `null` on
`framework.graphql_mock` means no local GraphQL mock is present.

| Key                         | Required | Type           | Default | Notes                                                            |
| --------------------------- | -------- | -------------- | ------- | ---------------------------------------------------------------- |
| `framework.ui`              | yes      | string         | —       | UI + styling layer, e.g. `mui-v7` (Material UI v7 + Emotion).    |
| `framework.state`           | no       | string         | —       | State manager, e.g. `zustand`.                                   |
| `framework.di`              | no       | string         | —       | DI container, e.g. `tsyringe` (reflect-metadata).                |
| `framework.router`          | no       | string         | —       | Router, e.g. `react-router-v6`.                                  |
| `framework.bundler`         | no       | string         | —       | Build tool, e.g. `rsbuild` (Rspack).                             |
| `framework.package_manager` | no       | string         | —       | Dependency manager, e.g. `bun` (deps only; lockfile `bun.lock`). |
| `framework.runtime`         | no       | string         | —       | JS runtime, e.g. `node-24`.                                      |
| `framework.i18n`            | no       | string         | —       | i18n library, e.g. `react-i18next` (uk default, en fallback).    |
| `framework.graphql_mock`    | no       | string \| null | `null`  | Local dev GraphQL mock, e.g. `apollo-server`; `null` = none.     |

## `architecture`

Mirrors the modular bulletproof-react layout. Skills resolve every concrete
path through these keys rather than hardcoding a repo's directories.

| Key                             | Required | Type   | Default | Notes                                                                     |
| ------------------------------- | -------- | ------ | ------- | ------------------------------------------------------------------------- |
| `architecture.source_root`      | yes      | string | —       | Usually `src`.                                                            |
| `architecture.modules`          | yes      | list   | —       | At least one feature-module directory name under `<source_root>/modules`. |
| `architecture.component_prefix` | no       | string | `UI`    | Prefix for reusable UI components (e.g. `UIButton`).                      |
| `architecture.path_aliases`     | no       | list   | —       | Import aliases configured in tsconfig/bundler/jest, e.g. `@/`, `@auth/`.  |

## `make` — logical target map

The `make` map is **required and must be complete**: every key below must
be declared. The value is the actual Make target name in the target
repository. An explicit `null` value means **capability absent**: the
plugin skips or degrades the dependent behavior with a note instead of
failing (never improvises a raw host command; generic tooling like `gh`,
`bun`, `git` may still be invoked directly when needed). Omitting a key
entirely is a validation error — the distinction between "absent capability"
and "forgot to declare" is intentional.

| Key                           | Required       | Default target           | Capability                                                                                                                                                                                                    |
| ----------------------------- | -------------- | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `make.ci`                     | yes (nullable) | `ci`                     | Full local CI suite.                                                                                                                                                                                          |
| `make.start`                  | yes (nullable) | `start`                  | Boot the dev server + API mock (containers).                                                                                                                                                                  |
| `make.start_prod`             | yes (nullable) | `start-prod`             | Boot the production build (E2E / visual / Lighthouse host).                                                                                                                                                   |
| `make.build`                  | yes (nullable) | `build`                  | Build the app (RSBuild).                                                                                                                                                                                      |
| `make.lint`                   | yes (nullable) | `lint`                   | Aggregate lint suite.                                                                                                                                                                                         |
| `make.lint_eslint`            | yes (nullable) | `lint-eslint`            | ESLint gate.                                                                                                                                                                                                  |
| `make.lint_tsc`               | yes (nullable) | `lint-tsc`               | TypeScript type-check.                                                                                                                                                                                        |
| `make.lint_md`                | yes (nullable) | `lint-md`                | Markdown lint.                                                                                                                                                                                                |
| `make.lint_dup`               | yes (nullable) | `lint-dup`               | jscpd copy/paste duplication gate.                                                                                                                                                                            |
| `make.lint_metrics`           | yes (nullable) | `lint-metrics`           | rust-code-analysis complexity gate.                                                                                                                                                                           |
| `make.lint_deps`              | yes (nullable) | `lint-deps`              | dependency-cruiser layer/import check.                                                                                                                                                                        |
| `make.format`                 | yes (nullable) | `format`                 | Prettier + qlty formatting.                                                                                                                                                                                   |
| `make.test_unit_client`       | yes (nullable) | `test-unit-client`       | Jest client (jsdom) unit tests.                                                                                                                                                                               |
| `make.test_unit_server`       | yes (nullable) | `test-unit-server`       | Jest server (node) unit tests.                                                                                                                                                                                |
| `make.test_integration`       | yes (nullable) | `test-integration`       | Jest integration tests (global 100% over `src`).                                                                                                                                                              |
| `make.test_e2e`               | yes (nullable) | `test-e2e`               | Playwright E2E.                                                                                                                                                                                               |
| `make.test_visual`            | yes (nullable) | `test-visual`            | Playwright visual regression; pair with `capabilities.visual_testing`.                                                                                                                                        |
| `make.test_mutation`          | yes (nullable) | `test-mutation`          | Stryker mutation testing; pair with `capabilities.mutation_testing`.                                                                                                                                          |
| `make.merge_mutation_reports` | yes (nullable) | `merge-mutation-reports` | Merge sharded mutation reports + re-enforce the Stryker `break` gate.                                                                                                                                         |
| `make.test_load`              | yes (nullable) | `test-load`              | k6 load tests; pair with `capabilities.load_testing`.                                                                                                                                                         |
| `make.test_memory_leak`       | yes (nullable) | `test-memory-leak`       | memlab memory-leak tests; pair with `capabilities.memory_leak_testing`.                                                                                                                                       |
| `make.lighthouse_desktop`     | yes (nullable) | `lighthouse-desktop`     | Lighthouse desktop audit; pair with `capabilities.lighthouse`.                                                                                                                                                |
| `make.lighthouse_mobile`      | yes (nullable) | `lighthouse-mobile`      | Lighthouse mobile audit; pair with `capabilities.lighthouse`.                                                                                                                                                 |
| `make.storybook_build`        | yes (nullable) | `storybook-build`        | Storybook static build; pair with `capabilities.storybook`.                                                                                                                                                   |
| `make.ai_review_loop`         | yes (nullable) | `null`                   | AI review loop; plugin substitutes `scripts/ai-review-loop.sh` when `null`.                                                                                                                                   |
| `make.pr_comments`            | yes (nullable) | `null`                   | PR comment listing; plugin substitutes `scripts/get-pr-comments.sh` when `null`.                                                                                                                              |
| `make.fr_nfr_gate`            | yes (nullable) | `null`                   | FR/NFR gate; plugin substitutes `scripts/fr-nfr-gate.sh` when `null`.                                                                                                                                         |
| `make.post_review_findings`   | yes (nullable) | `null`                   | PR-comment publisher; plugin substitutes `scripts/post-review-findings.sh` when `null`.                                                                                                                       |
| `make.a11y`                   | yes (nullable) | `null`                   | Accessibility audit; plugin runs its bundled a11y lane (axe-core / Playwright a11y probing + static checks) when `null`. Pairs with `capabilities.accessibility_audit` / `capabilities.dynamic_a11y_testing`. |

`make.ai_review_loop`, `make.pr_comments`, `make.fr_nfr_gate`,
`make.post_review_findings`, and `make.a11y` ship a `null` default; the
plugin substitutes its bundled `scripts/*.sh` (or, for `make.a11y`, its
static a11y lane) when the mapping is `null`. This mirrors the same
null-substitution precedent across the review-machinery targets.

## `quality` — raise-only thresholds

Shipped defaults are the **minimum bar**. A profile may tighten the bar,
never relax it:

- Floors (`quality.coverage_*`, `quality.mutation_msi`,
  `quality.lighthouse_desktop`, `quality.lighthouse_mobile`) may be
  **raised** above the defaults, never lowered.
- Ceilings (`quality.jscpd_clones`, `quality.eslint_errors`,
  `quality.eslint_warnings`, `quality.tsc_errors`,
  `quality.markdownlint_errors`, `quality.depcruise_violations`,
  `quality.visual_diffs`) ship at `0` and may not be raised — allowing more
  violations would lower the bar.
- `quality.metrics_enforced` is a boolean toggle for the rust-code-analysis
  hard-fail gate; it must stay `true` (the authoritative policy lives in
  `config/metrics-policy.json`).

`validate-profile.sh` rejects any value on the wrong side of its default.

| Key                            | Required | Direction               | Shipped default                            |
| ------------------------------ | -------- | ----------------------- | ------------------------------------------ |
| `quality.coverage_statements`  | yes      | floor (raise-only)      | `100`                                      |
| `quality.coverage_branches`    | yes      | floor (raise-only)      | `100`                                      |
| `quality.coverage_functions`   | yes      | floor (raise-only)      | `100`                                      |
| `quality.coverage_lines`       | yes      | floor (raise-only)      | `100`                                      |
| `quality.mutation_msi`         | yes      | floor (raise-only)      | `stryker.config.mjs` `break` (e.g. `2.17`) |
| `quality.jscpd_clones`         | yes      | ceiling (fixed)         | `0`                                        |
| `quality.eslint_errors`        | yes      | ceiling (fixed)         | `0`                                        |
| `quality.eslint_warnings`      | yes      | ceiling (fixed)         | `0`                                        |
| `quality.tsc_errors`           | yes      | ceiling (fixed)         | `0`                                        |
| `quality.markdownlint_errors`  | yes      | ceiling (fixed)         | `0`                                        |
| `quality.depcruise_violations` | yes      | ceiling (fixed)         | `0`                                        |
| `quality.metrics_enforced`     | yes      | bool (must stay `true`) | `true`                                     |
| `quality.visual_diffs`         | yes      | ceiling (fixed)         | `0`                                        |
| `quality.lighthouse_desktop`   | yes      | floor (raise-only)      | `95`                                       |
| `quality.lighthouse_mobile`    | yes      | floor (raise-only)      | `85`                                       |

`quality.mutation_msi` is seeded from the target repo's
`stryker.config.mjs` `break` threshold and is raise-only thereafter: the
mutation gate is enforced against whichever is higher. `make.test_mutation`
plus `make.merge_mutation_reports` re-enforce the same `break` after
merging sharded reports.

## `ci`

| Key                  | Required       | Type           | Default | Notes                                                                                                                                        |
| -------------------- | -------------- | -------------- | ------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `ci.provider`        | yes (nullable) | string \| null | —       | `github-actions`, or explicit `null` = no CI: `/fe-sdlc-finish-pr` skips check-waiting with a degrade note. The key itself must be declared. |
| `ci.workflows`       | no             | list           | `[]`    | Workflow names detected in the repository.                                                                                                   |
| `ci.required_checks` | no             | list           | `[]`    | Check names that must be green before a PR is finished.                                                                                      |

## `review`

| Key                               | Required | Type | Default    | Notes                                                                                                                |
| --------------------------------- | -------- | ---- | ---------- | -------------------------------------------------------------------------------------------------------------------- |
| `review.coderabbit`               | no       | bool | `false`    | True when `.coderabbit.yaml` exists; when false, `/fe-sdlc-finish-pr` uses the AI review loop as its comment source. |
| `review.ai_review_agents`         | no       | list | `[claude]` | v1 supports `claude` only; other entries warn-and-skip.                                                              |
| `review.request_changes_blocking` | no       | bool | `true`     | Whether a CHANGES_REQUESTED review blocks finishing.                                                                 |

## `capabilities`

Each boolean defaults to `false` (opt-in). A `false` (or absent) capability
makes the dependent skill skip-with-note rather than fail; it never weakens
a quality threshold. Where a capability pairs with a `make.*` target, both
must be present for the lane to run.

| Key                                 | Required | Type | Default | Notes                                                                                                                                                                                                                                                                              |
| ----------------------------------- | -------- | ---- | ------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `capabilities.visual_testing`       | no       | bool | `false` | Gates the visual-regression skill and the `quality.visual_diffs` lane; pairs with `make.test_visual`.                                                                                                                                                                              |
| `capabilities.lighthouse`           | no       | bool | `false` | Gates the Lighthouse performance skill and the `quality.lighthouse_desktop` / `quality.lighthouse_mobile` floors; pairs with `make.lighthouse_desktop` / `make.lighthouse_mobile`.                                                                                                 |
| `capabilities.mutation_testing`     | no       | bool | `false` | Gates the mutation-testing skill and the `quality.mutation_msi` floor; pairs with `make.test_mutation`.                                                                                                                                                                            |
| `capabilities.storybook`            | no       | bool | `false` | Gates the Storybook story-writing skill; pairs with `make.storybook_build`.                                                                                                                                                                                                        |
| `capabilities.load_testing`         | no       | bool | `false` | Gates load-test skills; pairs with `make.test_load`.                                                                                                                                                                                                                               |
| `capabilities.memory_leak_testing`  | no       | bool | `false` | Gates the memlab leak-detection skill; pairs with `make.test_memory_leak`.                                                                                                                                                                                                         |
| `capabilities.figma`                | no       | bool | `false` | Gates the figma-design-check skill (skip-with-note when false).                                                                                                                                                                                                                    |
| `capabilities.observability`        | no       | bool | `false` | Gates the observability-instrumentation skill (web-vitals / RUM wiring); skip-with-note when false.                                                                                                                                                                                |
| `capabilities.accessibility_audit`  | no       | bool | `false` | Gates the **static** accessibility lane (axe-core / ARIA / semantic checks); pairs with `make.a11y`.                                                                                                                                                                               |
| `capabilities.dynamic_a11y_testing` | no       | bool | `false` | Gates **dynamic** (live-browser) a11y probing in the accessibility auditor; pairs with `make.start` the way `capabilities.load_testing` pairs with `make.test_load`. When `false` (or `make.start: null`), dynamic probing degrades to skip-with-note; the static lane still runs. |
| `capabilities.publish_pr_comments`  | no       | bool | `false` | Gates the Publish step + the poster's write path (default OFF / opt-in); when false/absent the Publish step and the poster skip-with-note.                                                                                                                                         |

## `companion`

The optional ui-skills.com companion suite (design / motion / accessibility).
These keys are **non-validated** — they sit outside the checked prefixes, so
`validate-profile.sh` neither requires nor constrains them. `generate-profile.sh`
seeds a default block and `scripts/install-companion-skills.sh` consumes it during
`/fe-sdlc-setup` to install only the companions absent from the user config dir
(never the repo tree). Absent entirely, the companion step is a no-op.

| Key                         | Required | Type   | Default  | Notes                                                                                                                                                            |
| --------------------------- | -------- | ------ | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `companion.skills`          | no       | list   | curated  | Companion skill names installed on demand (e.g. `design-taste-frontend`, `frontend-design`, `make-interfaces-feel-better`, `interaction-design`, `oklch-skill`). |
| `companion.agents`          | no       | list   | curated  | Companion agent names (e.g. `accessibility-lead`, `aria-specialist`, `keyboard-navigator`, `contrast-master`, `forms-specialist`).                               |
| `companion.install_command` | no       | string | `manual` | Install mode: `manual` (report + point at `docs/companion-skills.md`), `plugin` (`claude plugin install <name>`), or a shell template containing `{name}`.       |

## Validation

```bash
"${CLAUDE_PLUGIN_ROOT}/scripts/validate-profile.sh" [PROFILE_FILE]
```

Defaults to `<cwd>/.claude/react-sdlc.yml`. Prints one `VIOLATION:` line
per finding (all findings, not just the first) and exits `0` when valid,
`1` otherwise. Violation classes: missing/undeclared required key, illegal
enum value, threshold on the wrong side of its shipped default (floor
lowered or ceiling raised), unsupported `schema_version`, and an incomplete
`make` map.

## For skill authors

Reference profile keys as inline code with the full dotted path (e.g.
`architecture.source_root`, `make.ci`, `quality.lighthouse_mobile`) and
list every consumed key under a `## Profile keys consumed` heading at the
top of the skill body. The `profile-keys-check` lint greps that list
against this page; an undeclared key fails the build. Concrete upstream
values (the VilnaCRM / ui-skills.com reference set) may appear only inside
fenced blocks whose opening fence carries the `# profile-example` marker.
